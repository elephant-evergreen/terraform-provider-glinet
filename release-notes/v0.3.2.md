## Upgrade notes

Existing configurations and state need no changes.

- A state written before v0.3.2 without an owner token now plans `owner` as known after apply when a resource changes. The first change records a token; later plans are empty again. A plan with no other change stays empty, so upgrading alone does not rewrite anything.
- Destroying a resource with `delete_behavior = "forget"` now clears `terraform_owner_id` on the router. Previously the token stayed behind, and creating the same section again could be refused as owned by another configuration.
- Changing `glinet_system_ssh` now activates dropbear and requires `allow_network_disruption = true`, because SSH carries the management path. Authentication, interface, idle timeout, and same-port changes activate inside the transaction and are verified by the confirmation connection. Disabling SSH or moving it to another port applies the configuration, activates the service after the transaction commits, and plans a warning; update the provider's `port` and `known_hosts_file` (or use the console) before the next operation, and apply that change on its own.
- Changes to packages that previously only wrote UCI now activate their stock service where one exists. A failed activation rolls the transaction back. Mesh, repeater, and site-to-site VPN changes now require `allow_network_disruption = true` for the same management-path reason.
- A transaction now commits only the UCI packages it changes instead of every managed package. This reduces flash writes and keeps the rollback snapshot unchanged. `GLINET_TRANSACTION_LOG` records the commit count per transaction.

## Fixes

- **A rollback could be reported before it completed.** The recovery worker recorded a rollback decision as the final outcome before restoring configuration, so the provider could report a completed rollback while restoration was still failing. The worker now records `restoring`, `restored`, and `restore_failed` separately, and only records `restored` after every snapshotted package and service activation has finished. The provider reports rollback success only for `restored`, an explicit failure for `restore_failed`, and an unconfirmed outcome while a restore is still running. A failed restore keeps its snapshot and recovery service for inspection.
- **A lost confirmation response could fail a committed apply.** If the confirmation command lost its SSH response after the router recorded a confirmed transaction, the provider eventually reported an unconfirmed failure and Terraform kept the old state. The provider now reads the durable decision first and reports a committed transaction as success. An unconfirmed transaction still fails.
- **Forget left the owner token on the router.** `delete_behavior = "forget"` now deletes `terraform_owner_id` together with clearing the marker.
- **Owner checks were not atomic with the write.** Both Terraform states could read an unowned section and then write it in turn. The provider now re-checks the observed owner inside the router-side transaction lock, before it prepares the transaction, and refuses a section claimed by another state without changing configuration.
- **The first update from a legacy state could fail Terraform's result consistency check.** v0.3.1 kept `owner = null` in the plan while the update wrote a token, which could produce "Provider produced inconsistent result after apply". A legacy state that changes now plans the owner as unknown, and the applied token matches. Protocol tests run the plan and apply with a v0.3.0/v0.3.1 state shape.
- **Service activation did not cover every managed package.** The transaction now activates the system hostname/time zone, OpenWrt LED setup, GL.iNet QoS, mesh, repeater, site-to-site VPN, WireGuard server, hardware acceleration, and WAN access (through the firewall). A fixture test fails when a writable UCI package has no reload path, service activation, cloud call, or recorded exemption.
- **`glinet_network_interface.metric` was rejected by preflight.** The provider now accepts and writes the metric option.
- **Plan-time validation for names and enumerated values.** Empty section names and invalid QoS, filter-list, and route-policy kinds now fail at plan time instead of during apply.

## Testing

- The recovery state machine is now covered by a Rapid model that drives the real restore script through failed copies, failed service activation, retries, and repeated completion. It checks that success is recorded only after a complete restore and that a retry converges.
- Property tests generate non-default attribute values through the schema validators, check that selector/load round trips preserve every explicit setting, and that only registered UCI options are written.
- Transaction timing, commit count, restart counts, and reboot counts can be recorded locally with `GLINET_TRANSACTION_LOG`.
- The coverage matrix is checked against the registered resource, data source, and action set, so documentation and implementation cannot drift apart silently. See [performance](https://github.com/elephant-evergreen/terraform-provider-glinet/blob/v0.3.2/docs/performance.md).

## Compatibility

The provider still supports Flint 2 (GL-MT6000) with stock firmware 4.11.x in router mode. The changes are fixture-verified. The hardware acceptance suite has not been re-run against this build; run `mise run acceptance` against an authorized router before relying on the SSH activation and recovery outcome changes on hardware, and record power-loss, SSH-disconnect, and restore-failure results in the private verification notes.
