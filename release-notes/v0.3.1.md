## Upgrade notes

Existing configurations and state need no changes. Upgrading from v0.3.0 now produces an empty plan; the owner token is recorded on the next write.

## Fixes

- The first plan after v0.3.0 showed an in-place update for every typed resource because the computed `owner` attribute was unknown in the plan while the state had no owner. The plan now keeps the prior owner value, so a legacy state plans no changes and avoids service reloads.

## Compatibility

The v0.3.0 code passed the hardware acceptance suite. The v0.3.1 change is limited to plan preservation and is covered by a unit test and a plan against the existing configuration.
