## Breaking changes

### Network, Wi-Fi, and GoodCloud changes need explicit permission

Starting with v0.3.0, an apply that would reload the network, reload Wi-Fi, or change the GoodCloud state stops with a diagnostic unless the provider is allowed to interrupt the connection. This affects `glinet_network_interface`, `glinet_network_bridge`, `glinet_ethernet_port`, `glinet_wireless_interface`, `glinet_wireless_radio`, `glinet_network_mode`, `glinet_goodcloud`, and any change that reloads the network or Wi-Fi.

Set `allow_network_disruption = true` in the provider block, or set `GLINET_ALLOW_NETWORK_DISRUPTION=true`, after confirming a wired recovery path and an encrypted backup. The provider still verifies the wired management path and takes the backup before the change. Existing configurations and state need no changes other than this setting. The reboot action keeps its `confirm = "REBOOT"` requirement.

### Service restarts on configuration changes

An apply now restarts the stock service that owns a changed package and waits for the service process when the service is enabled. Restarted services include Samba, OpenVPN, NTP, Tailscale, SQM, AdGuard Home, MiniDLNA, UPnP, ZeroTier, Tor, multi-WAN, timers, client filters, parental control, policy routing, DDNS, DPI, full-cone NAT, the status LED, and uhttpd. A change can briefly interrupt the restarted service, for example an OpenVPN session or traffic shaping. The rollback runs the same activation against the restored configuration.

## Upgrade notes

- Existing configurations and state need no changes, but network, Wi-Fi, and GoodCloud changes require `allow_network_disruption` as described above.
- The first write of a typed resource records an owner token in the section and in the computed `owner` attribute. The option is additive; configurations and imports need no changes. Legacy sections with only the ownership marker are adopted on their next write.
- A provider without owner-token support can rewrite a section without the token; the next write with v0.3.0 regenerates it.
- Firmware 4.11.x in router mode remains the supported and verified line.

## Highlights

- Record a per-section owner token and refuse Create, Update, and Delete when another Terraform state owns the section.
- Restart the stock service that owns a changed package and verify its process when the service is enabled.
- Report an explicit rollback outcome (rolled back, already committed, cancelled, superseded, unknown) and request the rollback without a long-lived SSH command.
- Exclude password, secret, token, PSK, and key options from the safety state for every package, including the PPPoE password.
- Add a hardware acceptance suite with unique names, direct router observation, `CheckDestroy`, and lock and recovery checks.
- Add state-upgrader support, property-based selector tests, more fuzz targets, benchmarks, and a documentation index.

## Fixes

- Deleting a managed firewall section with `delete_behavior = "delete"` no longer fails with `An unmanaged enabled port redirect exists`.
- Deleting a section that lost its ownership marker is refused instead of removing an unmanaged section.
- Property tests cover every typed selector and require the selector to reach a stable form and to write only registered options.
- The confirmation-wait test and the rollback test no longer race the router worker.

## Compatibility

Live checks for this release covered the upgrade path, existing configurations, firewall and forwarding changes, a declared redirect, a failed verification with rollback, router-side recovery after an SSH disconnection, reboot, service activation, and the owner-token path. Traffic acceptance across each network and power-loss recovery remain manual checks. See the [verification boundaries](https://github.com/elephant-evergreen/terraform-provider-glinet/blob/v0.3.0/docs/testing.md).
