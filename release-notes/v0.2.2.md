## Upgrade notes

Existing configurations and state need no changes.

- Options added to a resource after v0.2.1 keep the value read from the router when the configuration omits them, so upgrading does not rewrite settings that the configuration never managed. Declare an option to manage its value.
- `glinet_firewall_rules` updates a rule in place when its name stays the same, fills omitted fields with the values that are written, and accepts renaming a rule to a name that another rule is leaving.
- `glinet_firewall_forwarding` updates a changed source or destination in place. Set `delete_behavior = "delete"` to remove the anonymous forwarding on destroy; the default `forget` releases ownership and keeps the section.
- `glinet_network_mode` accepts only `router`, because every provider operation requires router mode.
- Options stored as lists are sets: MiniDLNA `media_dir`, the uhttpd `listen_http` and `listen_https` addresses, the route policy `append_source_if`, and the policy rule `from`. Configurations that set them as strings must switch to a set.
- The provider retries the runtime firewall check briefly and rolls the transaction back when verification or confirmation fails. The router-side recovery still restores unconfirmed changes after 300 seconds.

## Highlights

- Manage the stock operating mode and connectivity tracking, static routes and policy routing rules, multi-WAN members, the drop-in gateway and its DHCP helper, and the firewall defaults.
- Adopt a Wi-Fi radio with `glinet_wireless_radio`, and manage the stock mesh and repeater settings.
- Manage MAC filters and per-network isolation, WAN access, and parental control.
- Manage DDNS, Samba and its shares, MiniDLNA, UPnP, AdGuard Home, DPI and content protection, full-cone NAT, hardware acceleration, the status LED, QoS and SQM.
- Manage the OpenVPN client and servers, Tailscale, ZeroTier, Tor, the WireGuard global switch and server, and site-to-site settings.
- Manage system identity, NTP, SSH, per-LED settings, and admin access, plus scheduled timers for Wi-Fi, LEDs, and reboots.
- Manage the stock GoodCloud switch through `cloud.set_config`.
- Read the DHCP lease table with the `glinet_clients` data source.
- Run the `glinet_backup` and `glinet_reboot` actions.

## Fixes

- Import and refresh work for `glinet_minidlna`, `glinet_system_ssh`, `glinet_admin_access`, `glinet_sqm`, `glinet_openvpn_server`, `glinet_system_ntp`, and `glinet_adguard`. Previously they failed with an undeclared attribute or could not find the stock section.
- `glinet_qos_interface` and `glinet_route_policy_rule` accept their documented `kind:section` import identifiers.
- Selectors no longer write options that their schema does not declare, so applying a resource no longer deletes settings it never managed.
- List-valued options are written as lists and read back correctly.
- Anonymous singletons store the resolved section name after an update.
- Resetting a numeric option to zero removes the option instead of leaving the previous value.
- Adding a rule to `glinet_firewall_rules` no longer produces an inconsistent result.
- Actions receive the router client, so `glinet_backup` and `glinet_reboot` run.
- Register the UCI scopes and options used by the newer resources, including the policy rule scopes, multi-WAN tracking list, parental control source list, and the stock `/etc/firewall.vpnclient` include.

## Compatibility

Live checks for this release exercised the existing configuration, firewall policy and forwarding, multi-WAN, system, NTP, DNS, timers, SQM and QoS, DPI, content protection, full-cone NAT, the drop-in gateway, the GoodCloud switch, and the VPN integrations on stock firmware 4.11.2. Settings that would interrupt the live network were adopted and read without changing the switch. Fixture and protocol tests cover the resource contracts; they do not replace live checks.

Firmware 4.11.0 remains the verified build, and stable 4.11.x patches are allowed with a warning. WireGuard support remains experimental.
