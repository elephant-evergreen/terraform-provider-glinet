## Upgrade notes

Existing configurations and state need no changes. This release adds the `glinet_goodcloud` singleton resource.

## Highlights

- Add `glinet_goodcloud` to manage the stock GoodCloud switch. The resource calls the router's stock `cloud.set_config` operation instead of writing the enable flag directly, so the stock transition still stops `rtty`, may stop `mptun` and `mpifd`, removes the local `bindtime`, and may set `mptun.global.enable=0`.
- Snapshot the GoodCloud UCI package and service runtime states separately. Rollback restores configuration files and then attempts to restore the recorded service states; a state that cannot be confirmed is reported for inspection.
- GoodCloud changes require a direct wired management path, like other disruptive changes in this provider.
- Destroy releases provider ownership without changing the current switch value.

## Hardware status

Fixture and Terraform protocol tests cover the resource and the service transaction. Hardware acceptance is not included in this release; record the exact firmware and provider version in the hardware verification notes when it is performed.
