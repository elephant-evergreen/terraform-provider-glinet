## Upgrade notes

This release replaces `glinet_firewall_rule` with `glinet_firewall_rules`. The ordered policy owns rule content, membership, and order; `position` is removed.

To migrate:

1. Import the existing rule set as `firewall_rules`.
2. List every current firewall rule in UCI order.
3. Mark stock rules with `existing = true`; their content is preserved.
4. Remove the old `glinet_firewall_rule` resources from state without destroying the rules.
5. Run `terraform plan` and confirm that the same rules are not replaced or deleted.

## Breaking changes

- Remove the per-rule `glinet_firewall_rule` resource and its `position` attribute.
- Add the singleton `glinet_firewall_rules` resource with an ordered `rules` list.
- A policy must list every UCI firewall rule exactly once. Missing rules are rejected instead of being silently ignored.
- Existing stock rules use `existing = true`; their current options and lists are preserved.
- Stock rules that share a `name` are distinguished by `src` and `dest`; the ordered list must identify each rule uniquely.
- Removing a managed rule from the list deletes it. Removing an existing stock rule from the list is rejected.
- Destroy releases provider ownership and preserves the current rule sections.

## Behavior

- Rule content, membership, and order are written in one recovery-protected configuration transaction.
- Non-rule firewall sections do not change the policy order.
- Firewall evaluation remains per chain. The list order is UCI rule order, not a global cross-chain precedence.
- The provider keeps its runtime firewall checks; a configuration transaction is not a packet-level atomic switch.

## Hardware status

Fixture and Terraform protocol tests cover the new policy boundary. No hardware acceptance is included in this release; record the exact firmware and provider version in the hardware verification notes when it is performed.
