## Upgrade notes

Existing configurations and state need no changes. This release adds the ordered `glinet_firewall_rules` resource while keeping `glinet_firewall_rule` available for migration.

## Highlights

- Add `glinet_firewall_rules`, a singleton ordered policy that owns rule content, membership, and order in one recovery-protected transaction.
- Keep `glinet_firewall_rule` and its `position` attribute for existing configurations. It is deprecated; use the ordered policy for new or order-sensitive rules.
- Stock rules are listed with `existing = true` and preserve their current content. Do not use `glinet_firewall_rule` and `glinet_firewall_rules` for the same rule.
- The provider writes the `terraform_owner` marker and reads the legacy `home_iac_owner` marker during migration. The next write migrates legacy-marked sections to `terraform_owner`.

## Compatibility

This is an additive 0.1.x release. The breaking removal of `glinet_firewall_rule`, `position`, and the legacy marker is reserved for 0.2.0 after a migration period.

## Hardware status

Fixture and Terraform protocol tests cover both resource paths. No hardware acceptance is included in this release; record the exact firmware and provider version in the hardware verification notes when it is performed.
