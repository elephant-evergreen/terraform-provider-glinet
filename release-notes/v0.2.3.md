## Upgrade notes

Existing configurations and state need no changes.

- Firmware 4.11.0, 4.11.2, and 4.11.3 in router mode are now the hardware-verified builds. Other stable 4.11.x patches remain allowed with the untested-build warning.
- Destroying a provider-managed firewall section with `delete_behavior = "delete"` no longer stops at the safety check: a section that the transaction removes is recognised as managed, while an unmanaged section is still rejected.

## Fixes

- Deleting a `glinet_firewall_redirect` failed with `An unmanaged enabled port redirect exists` because the safety check could not see the section that the transaction was removing. The check now also treats a running section with the provider marker as managed, so managed redirects, forwardings, and ACCEPT rules can be deleted while unmanaged ones still block the apply.

## Compatibility

Hardware checks on 4.11.2 and 4.11.3 covered the upgrade path, the existing configuration plan, forwarding and firewall rule changes, a declared port redirect, a verification failure with rollback, router-side recovery after an SSH disconnection, and reboot. Traffic acceptance across each network and power-loss recovery remain separate manual checks.
